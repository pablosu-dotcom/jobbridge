```text
jobbridge
```

Character set:


## 2. Organizations Table

```sql
CREATE TABLE organizations (
    id VARCHAR(36) PRIMARY KEY,
    owner_user_id VARCHAR(255) NOT NULL,
    name VARCHAR(150) NOT NULL,
    website VARCHAR(255),
    contact_name VARCHAR(150) NOT NULL,
    contact_email VARCHAR(255) NOT NULL,
    description TEXT,
    status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
    reviewed_by VARCHAR(255),
    reviewed_at TIMESTAMP NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_organizations_owner_user_id (owner_user_id)
);
```

### Column definitions

| Column | Purpose |
|---|---|
| `id` | UUID generated by the integration |
| `owner_user_id` | Asgardeo user subject identifier |
| `name` | Organization display name |
| `website` | Public organization URL |
| `contact_name` | Primary contact |
| `contact_email` | Primary contact email |
| `description` | Organization description |
| `status` | `PENDING`, `ACTIVE`, or `REJECTED` |
| `reviewed_by` | Future administrator user ID |
| `reviewed_at` | Review timestamp |
| `created_at` | Creation timestamp |

### Lifecycle values

```text
PENDING
ACTIVE
REJECTED
```

## 3. Jobs Table

The exact deployed schema should match the existing local table. A baseline design is:

```sql
CREATE TABLE jobs (
    id VARCHAR(36) PRIMARY KEY,
    title VARCHAR(150) NOT NULL,
    organization VARCHAR(150) NOT NULL,
    location VARCHAR(150) NOT NULL,
    employment_type VARCHAR(50) NOT NULL,
    description TEXT NOT NULL,
    apply_url VARCHAR(500) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### Column definitions

| Column | Purpose |
|---|---|
| `id` | UUID generated by the integration |
| `title` | Job title |
| `organization` | Current organization display name |
| `location` | Job location |
| `employment_type` | Full-time, part-time, contract, etc. |
| `description` | Job description |
| `apply_url` | External application URL |
| `status` | `PENDING`, `ACTIVE`, or `REJECTED` |
| `created_at` | Submission timestamp |

## 4. Recommended Relationship Improvement

Jobs should reference the approved organization by ID.

```sql
ALTER TABLE jobs
ADD COLUMN organization_id VARCHAR(36),
ADD CONSTRAINT fk_jobs_organization
    FOREIGN KEY (organization_id)
    REFERENCES organizations(id);
```

After migration, the integration should derive `organization_id` from the authenticated user rather than accepting an arbitrary organization name.

Target relationship:

```text
organizations
    id
     |
     | one-to-many
     v
jobs
    organization_id
```

## 6. Recommended Audit Table

```sql
CREATE TABLE review_audit (
    id VARCHAR(36) PRIMARY KEY,
    entity_type VARCHAR(30) NOT NULL,
    entity_id VARCHAR(36) NOT NULL,
    action VARCHAR(30) NOT NULL,
    performed_by VARCHAR(255) NOT NULL,
    reason TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

Example values:

```text
entity_type: ORGANIZATION or JOB
action: APPROVED or REJECTED
```
